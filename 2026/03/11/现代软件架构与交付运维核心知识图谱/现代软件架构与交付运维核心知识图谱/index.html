云原生架构&&安全

XaaS

  • IaaS（Infrastructure-as-a-Service基础设施即服务）： 提供给消费者的服务是对所有设施

的利用，包括处理、存储、网络和其它基本的计算资源，用户能够部署和运行任意软件，包

括操作系统和应用程序。主要功能就是讲底层的硬件资源以服务的方式对外暴露，为上层提

供服务。IaaS模式下，只提供云计算服务的基础设施，用户可以部署和运行任意软件

  • 国内主流IaaS代表：

    • 阿里云
    • 腾讯云
    • 华为云

  • 国际主流IaaS代表：

  • AWS（亚马逊云）

  • Azure（微软）

  • SaaS（Software-as-a-Service软件即服务）： 提供给客户的服务是运营商运行在云计算基

础设施上的应用程序，用户可以在各种设备上通过客户端界面访问，如浏览器。SaaS模式

下，用户可以直接通过客户端使用云计算服务，不需要管理任何软硬件

  • 国内主流SaaS代表：

    • 企业办公：企业微信，钉钉，飞书
    • 云文档：腾讯文档、石墨文档、语雀
    • 邮箱：网易企业邮箱、腾讯企业邮
    • 安全类 SaaS：奇安信天擎 SaaS、安恒云盾、微步在线 SaaS

  • 国际主流 SaaS 代表：

    • 办公协作：Microsoft 365、Google Workspace
    • CRM（Customer RelationShip Management）：Salesforce
    • 项目管理：Notion、Asana、Trello

  • PaaS（Platform-as-a-Service平台即服务）： 是云计算的重要组成部分，提供给消费者的

服务是把客户采用提供的开发语言和工具开发的或收购的应用程序部署到供应商的云计算基

础设施上去。PaaS模式下，用户不需要管理和控制云计算底层基础设施，直接使用和控制应

用程序即可。

  • 典型的PaaS产品：
    • 腾讯云 云开发 CloudBase
    • Azure App Service
    • AWS Elastic Beanstalk
  • BaaS（Backend as a Service）后端即服务： 应用架构由大量第三方云服务器和API组成

的，使应用中关于服务器的逻辑和状态都由服务提供方来管理的。比如典型的Web应用和移

动APP客户端应用，前后端交互主要是以RestAPI调用为主。只需要调用服务提供方的API即

可完成相应的功能，比如常见的身份验证，云端数据/文件存储，消息推送，应用数据分析

等。

  • 典型BaaS：

    • 阿里云 移动后端服务（MBaaS）：集成阿里云数据库、存储、消息推送。

  • FaaS（Function as a Service）函数即服务： 是一种实现无服务器计算的方法，服务商提

供一个平台，允许客户开发、运行和管理应用程序功能，而无需构建和维护通常与开发和启

动应用程序相关的基础架构的复杂性。 按照此模型构建应用程序是实现“无服务器”体系结构

的一种方式，通常在构建微服务应用程序时使用。

云原生

  • Kubernetes： 简称k8s，用8代替名字中间的8个字符“ubernete”而成的缩写。是Google开源

的一个容器编排引擎，用于管理云平台中多个主机上的容器化的应用，Kubernetes的目标是

让部署容器化的应用简单并且高效（powerful），Kubernetes提供了应用部署，规划，更

新，维护的一种机制。可以理解为云原生的操作系统，用以管理容器，Pod，节点，网络，

存储，服务。

  • Pod：Kubernetes 里最小的调度单元，一个 Pod 里可以装 1 个或多个紧密相关的容器，同

一个 Pod 里的容器，共享 IP，端口空间 ，且存储卷一定在 同一个 Node（机器） 上，作为

服务真正运行起来的实例，载体。

  • 容器（Container）：将应用与依赖环境封装在一起的轻量级隔离运行单元。典型的代表：

Docker。

  • Deployment：用以管理 Pod 的 “管理员 / 控制器”，通过控制副本数与声明式配置，实现

Pod 的自动化创建、自愈、扩缩容、滚动更新与版本回滚，确保应用始终处于期望的运行状

态。

  • 微服务：是一种分布式架构模式，将单一应用拆分为多个小型、自治、独立部署的服务单

元，各服务运行在独立进程中，通过轻量级通信机制（如 HTTP/REST、RPC）协同工作，

具备高可用、易扩展、技术栈灵活等优势。

  • REST 接口：是基于 HTTP 协议、遵循 REST 设计风格的应用程序编程接口，以资源为核

心，使用标准 HTTP 方法（GET/POST/PUT/DELETE）表示对资源的操作，具有无状态、接

口统一、易扩展等特点，是系统间交互的常用规范。

  • RPC（Remote Procedure Call，远程过程调用）：是一种分布式服务间的通信机制，它让

应用程序可以像调用本地函数一样，直接调用另一台服务器上的函数或服务，底层的网络传

输、序列化、连接等细节被完全屏蔽，使分布式调用像本地调用一样简单。

  • DevOps（Development&&Operations开发运维一体化）：核心就是持续集成和持续交

付，需要将软件生命周期过程中的从需求开始到设计程序的开发、编译构建打包部署，从测

试环境到生产环境整个过程能够实现全部的自动化。

  • Serverless（无服务器架构）：云原生发展到后期之后，云原生的核心就是实现从资源到服

务不算向上抽象，开发人员越来越不会接触到底层IT基础设施，只会接触各种技术服务能

力，这种技术服务能力在Serverless架构里叫做Baas（后端能力即服务）

  • Service Mesh：基于微服务架构搭建应用已成为主流的开发模式，微服务架构在带给我们一

系列便利的同时，仍然存在缺点，其中的核心问题就是如何管理服务间的网络管理和服务治

理，且这个问题会在应用规模变得越来越庞大时更加突出。Service Mesh技术就是为了解决

这些难题而生的。一句话概括Service Mesh就是微服务的网关，负载均衡等独立出来成为底

层基础服务，从架构上剥离微服务，让开发者只关心业务开发的技术。

深色 的是我们平时工作中接触最多的 业务微服务 ，旁边 蓝色 的被称为边车（sidecar）服

务，sidecar作为业务微服务的“代理”，处理与其他业务微服务sidecar之间的非功能需求，如

网络通信、安全、监控、流量控制等。多个sidecar之间的连接和交互组成了“网格

（mesh）”。

安全运营中心（Security Operations Center, SOC）

  • **UBA (User Behavior Analytics)**：UBA 是一种基于数据分析的安全技术，它通过建立用户

行为基线，利用统计模型和机器学习算法来检测与正常行为模式显著偏离的异常活动，旨在

识别内部威胁、账户盗用和恶意行为。

  • **UEBA (User and Entity Behavior Analytics)**：UEBA 是 UBA 的演进形态，它不仅分析用

户行为，还将分析范围扩展至实体（如服务器、设备、应用程序、服务账户等）。通过构建

实体间的行为关系图谱，UEBA 能够检测更复杂的攻击链，如横向移动和供应链攻击，从而

提供更全面的安全态势感知。

  • SOAR（Security Orchestration, Automation and Response）：是一种安全技术平台，

它通过集成各类安全工具、编排响应流程、自动化执行重复性任务，来提升安全运营中心

（SOC）处理安全事件的效率与速度。

  • MITRE ATT&CK 框架（Adversarial Tactics, Techniques, and Common Knowledge）：是一

个基于真实世界观察的全球性知识库，用于描述和分类网络攻击者的行为。它通过战术

（Tactics）、技术（Techniques） 和子技术（Sub-techniques） 的三层结构，系统化地呈现

了攻击者在网络攻击生命周期中的行为模式，旨在为威胁检测、分析及防御提供标准化的参

考框架。

Jenkins

Jenkins 是一款开源的自动化服务器，主要用于实现持续集成（CI）和持续交付（CD）。它通过

自动化构建、测试和部署流程，帮助开发团队提高软件交付效率和质量。

在DevOps体系架构中属于工程自动化层。在 DevOps 实践中，Jenkins 可用于自动化执行设计

资产的版本管理、设计系统组件的构建与发布、以及设计稿与代码的同步验证等任务。

Selenium（Se）

Selenium是一种Web浏览器自动化工具，它用于模拟真实用户操作（如点击、输入、滚动），验

证 Web 应用的功能是否正常，替代大量重复的手工测试。

Nagios

Nagios 是一个用于监控主机、网络服务、应用程序状态的系统。它能在服务或系统出现故障时

立即发出告警，并在问题解决后发送恢复通知。

CI/CD概念：

CI（Continuous Integration）持续集成：

指开发人员频繁地（如每天多次）将代码集成到主干（如 Git 主分支）的实践。每次代码提交

（Push）后，系统（如 Jenkins）会自动触发构建（Build）和自动化测试（Test）。其目的是尽

早发现集成错误，避免开发后期出现“集成地狱”。

CD（Continuous Deployment or Continuous Delivery）持续部署or持续交付：

Continuous Delivery (持续交付)：指代码通过 CI 阶段的自动化测试后，可以随时手动一键

部署到生产环境。重点在于“可随时发布”，但发布动作由人工决策。

Continuous Deployment (持续部署)：指代码通过 CI 阶段后，自动部署到生产环境。重点

在于“全自动发布”，无需人工干预。

Kubernetes（k8s）
  1. 服务发现与负载均衡

容器是动态的，IP 地址会变。k8s 内置 DNS 服务，为每个服务分配一个固定的域名。当外部

请求访问时，k8s 会自动将流量分发到后端的多个健康容器实例上，实现负载均衡。

  1. 自动扩缩容 (Auto-scaling)

根据 CPU 使用率或自定义指标（如 QPS），自动增加或减少运行的容器数量。例如，双十

一流量暴增时自动扩容，凌晨流量低谷时自动缩容以节省资源。

  1. 自我修复 (Self-healing)

这是 k8s 最强大的功能之一。它会持续监控容器的健康状态。如果某个容器崩溃了，k8s 会自动杀死它并重新启动一个新容器；如果整个节点（服务器）宕机，k8s 会将该节点上的容

器自动迁移到其他健康的节点上运行，确保服务不中断。

  1. 存储编排

容器本身是“无状态”的（重启后数据丢失）。k8s 允许你挂载本地存储、网络存储（如

NFS、Ceph）或云存储，并自动完成挂载，让容器可以持久化保存数据。

  1. 自动发布与回滚

k8s 支持滚动更新。当你推送了新版本的镜像（如 my-app:v2.0 ），k8s 会逐步用新容器替

换旧容器，期间服务不中断。如果新版本有问题，可以一键回滚到之前的稳定版本。

  1. 配置与密钥管理

将应用的配置文件、数据库密码、API Key 等敏感信息从容器镜像中剥离，通过 ConfigMap

和 Secret 对象注入，既安全又便于不同环境（开发、测试、生产）切换配置。

  1. 资源调度与优化

k8s 的调度器会根据每台服务器的 CPU、内存剩余情况，智能地将容器调度到最合适的节点

上运行，最大化利用集群资源。

    安全架构学学习笔记：IT、OT、IOT与CIA

    Posted on 2026-03-24 Word count in article: 3.3k Reading time ≈ 3 mins.

    术语 全称 核心定位 定义
    IT Information Technology
    信息技术    		 企业信息
    中枢    		 负责处理、存储、传输业务数据，支撑企业办
    公、管理与决策的技术体系。
    OT Operational Technology
    运营技术    		 工业生产
    中枢    		 负责控制物理设备、保障工业产线 / 基础设施
    稳定运行的工控技术体系。
    IoT Internet of Things 物联网 通用连接
    技术    		 让各类物理设备（终端、传感器、机器）实现
    联网通信、数据采集与远程控制的技术总称。
    IIoT Industrial Internet of
    Things 工业物联网    		 工业专属
    连接层    		 IoT 技术在工业 OT 场景的落地，是打通 IT
    与 OT、实现工业智能化的核心技术载体。

    IT

    • standard： ISO/IEC 27001 / NIST CSF
    • CIA（Confidentiality, Integrity, Availability）：机密性 > 完整性 > 可用性

    通用组件

    1. 硬件基础设施
    • 边界网关：路由器、下一代防火墙（NGFW），负责出入网控制、NAT、VPN。核心交换：核心层交换机，承担内网高速转发、路由汇聚。
    • 接入交换：接入层交换机，连接电脑、AP、打印机等终端。
    • 无线系统：AC（无线控制器）+ Fit AP（瘦 AP），提供 Wi-Fi 覆盖。
    • 服务器与存储：应用服务器、数据库服务器、SAN/NAS 存储。
    • 终端设备：PC、笔记本、打印机、IoT 传感器。
    1. 软件与协议栈
    • 网络操作系统：EOS、IOS、NX-OS 等。
    • 路由协议：OSPF、BGP、静态路由。
    • 虚拟化技术：VXLAN、SDN（软件定义网络）。
    • 负载均衡：F5、Nginx、LVS（四层 / 七层流量调度）。
    • 安全组件：WAF（Web 应用防火墙）、IDS/IPS、AD（身份认证）。

    OT

    • standard： IEC 62443 系列
    • CIA（Confidentiality, Integrity, Availability）：可用性 > 完整性 > 机密性

    工业控制网络的分层架构（Purdue模型）

    Level 0：I/O Network（现场设备层 / 物理层）
    • 核心定位：最底层，直接和物理世界交互
    • 组件：传感器（Sensor）、执行器（Actuator）、智能现场设备（Smart Device）
    • 作用：采集现场数据（温度、压力、流量等）、执行控制指令（开关阀门、驱动电机）
    • 通信方式：通过直接 I/O 或串口协议（如 Modbus RTU、Profibus）和上层 PLC 通信
    • 归属：100% OT 领域，是工业控制的 “手脚”
    Level 1：Control Network（控制层）
    • 核心定位：现场控制的核心，负责实时逻辑控制
    • 组件：PLC（可编程逻辑控制器）、RTU（远程终端单元）、DCS 控制器
    • 作用：接收 Level 0 的传感器数据，运行控制逻辑，下发指令给执行器，保障产线实时运行通信方式：通过工业以太网协议（如 Modbus TCP、Profinet、EtherNet/IP）和上层监控系统通信
    • 归属：100% OT 领域，是工业控制的 “大脑”
    Level 2：Supervisory Control LAN（监控层 / supervisory 控制层）
    • 核心定位：全厂 / 车间级的集中监控与管理
    • 组件：
      • HMI（人机界面）：操作员用来监控产线、下发指令的操作终端
      • Historian / 实时工程数据库：存储历史生产数据，用于趋势分析、报表生成
      • 工程师工作站：用于组态、调试、维护 PLC 等控制设备
    • 作用：实现对 Level 1 控制网络的集中监控，是操作员和产线的交互窗口
    • 通信方式：工业以太网，和 Level 1 双向通信
    • 归属：OT 核心层，是 OT 系统的 “指挥中心”
    Level 3：Corporate Network（企业层 / IT 网络）
    • 核心定位：企业 IT 业务系统，和生产控制解耦
    • 组件：企业 IT 网络、服务器、办公系统、ERP、MES（制造执行系统，部分场景归 Level3）
    • 作用：负责企业的业务管理、资源调度、订单处理，和 Level 2 进行数据交互（如生产计划
      下发、生产数据上传）
    • 安全隔离：通过防火墙（Firewall） 和 Level 2 严格隔离，防止 IT 网络的攻击渗透到 OT 产
      线
    • 归属：100% IT 领域，是企业的 “业务中枢”
    Internet（互联网）
    • 定位：外部网络，企业 IT 网络通过防火墙接入互联网
    • 作用：支持远程办公、云服务、远程运维等，同时是网络攻击的主要入口

    IT & OT

    🟦 IT/OT 过渡层（融合与安全隔离核心）

    Level 3.5：IT/OT DMZ（非军事区）

    • 核心定位：IT 与 OT 之间的 “缓冲带” 和 “安全网关”，是现代工业网络的核心设计

    • 组件：

      • Patch Server（补丁服务器）：仅向 OT 域推送经过验证的安全补丁，避免直接从互联网更新
      • Historian mirror（历史数据库镜像）：将 OT 域 Historian 数据同步到 DMZ，供 IT 域访问，不直接暴露 OT 核心
      • Jump Server (Host)（主机跳转服务器）：IT 运维人员访问 OT 系统的唯一跳板，全程审计留痕
      • 防火墙：DMZ 与 IT 域、OT 域的双重隔离屏障

    • 作用：

    1. 彻底隔离 IT 与 OT 核心网络：IT 无法直接访问 OT 核心，OT 也无法直接访问互联网
    2. 受控数据交互：仅允许必要的生产数据、运维操作通过 DMZ 中转
    3. 安全审计：所有跨域访问都经过跳板机，全程可追溯、可管控
    • 通信：仅与 Level 3（OT）、Level 4/5（IT）受控通信，是 IT/OT 融合的唯一合法通道
    DMZ（Demilitarized Zone）

    DMZ（Demilitarized Zone，非军事区） 就是企业网络里的 “特殊隔离带 / 缓冲区”。

    1. 在普通 IT 架构里
    • 外网（互联网） ⟶ 防火墙 ⟶ DMZ 区（放 Web 服务器、邮件服务器） ⟶ 防火墙 ⟶ 内网（办公 / 数据库）。
    • 逻辑：
      • 黑客只能先打到 DMZ 里的 Web 服务器。
      • 即便 Web 服务器被攻破了，黑客也无法直接通过它跳到内部内网（因为中间还有一道防火墙）。
    1. 在上述IT/OT 架构图里
      图里的 Level 3.5 就是专门的 IT/OT DMZ：
    • 左边（OT 域）：是极其宝贵的生产网，断网就停产，绝对不能直接连互联网。
    • 右边（IT 域）：是企业办公网，也是安全重点。
    • 中间（DMZ / Level 3.5）：
      • Patch Server（补丁服务器）：OT 想打补丁，不能直接去互联网下载，必须先经过DMZ 的补丁服务器拉取安全补丁。
      • Historian mirror（镜像数据库）：OT 的生产数据（Historian）不能直接发给 IT 系统，必须先同步到 DMZ 的镜像库，供 IT 查看。
      • Jump Server（跳板机）：IT 工程师想远程维护 OT 的设备，不能直接连，必须先通过DMZ 的跳板机申请权限。

    IoT

    • standard： ETSI EN 303 645 / ISO/IEC 27400
    • CIA（Confidentiality, Integrity, Availability）：由于IoT横跨消费级设备和关键基础设施，因此取决于设备的具体用途
      • 场景 A：关键基础设施 IoT (如联网电表、智能交通灯、医疗监护仪)
        • 优先级：可用性 ≈ 完整性 > 机密性
        • 逻辑：类似 OT。如果心脏起搏器被黑客关闭（可用性丧失）或读数被篡改（完整性丧失），会直接危及生命。
      • 场景 B：消费级/隐私敏感 IoT (如智能摄像头、智能音箱、儿童手表)
        • 优先级：机密性 > 完整性 > 可用性
        • 逻辑：类似 IT。用户最担心的是家里被偷拍（机密性丧失）或语音数据被窃听。虽然设备被黑变成“僵尸网络”也很糟糕，但用户感知的最大痛点是隐私泄露。
      • 场景 C：大规模传感器网络 (如农业土壤监测)
        • 优先级：完整性 > 可用性 > 机密性
        • 逻辑：数据准不准（完整性）最重要；偶尔丢几个数据包（可用性）可以接受；土壤湿度数据本身没什么秘密（机密性低）。
